# PART I — Anomaly-Detection Baselines (Track A)

These three papers are being **directly reproduced** as baselines under a shared protocol (R8: identical data split, preprocessing, and tuning budget across all baselines and proposed models), so they receive the deepest coverage.

## 1. Villar et al. (2021) — Baseline 1 (VRAE + Isolation Forest)

**Problem.** Wide-field surveys (especially upcoming Rubin/LSST) will discover far more transients than can be spectroscopically followed up (<0.1%). The paper builds an anomaly-ranking pipeline to prioritize rare transients for follow-up, ideally before peak brightness.

**Dataset.** PLAsTiCC simulated Rubin/LSST data. After cuts (removing Milky-Way-only classes, SNe with fewer than 3 detections within 300 days of peak, and Deep Drilling Field events): 1,129,184 extragalactic light curves across 13 classes, six filters (*ugrizY*). Majority classes — Ia (54.2%), II (25.8%), Ibc (5.8%) — total ≈86%; minority classes are ≤2% each; AGN (6.3%) is treated separately.

**Preprocessing.** Magnitudes scaled to survey limit = 0; corrected for time dilation; converted to absolute magnitude via photometric redshift (color-matched nearest-neighbor estimator — ~17% of these z estimates are outliers by the paper's own criterion, and no cuts are made on this, it is instead handled via Monte Carlo); Galactic-reddening corrected; each event time-shifted so peak brightness sits at t = 0.

**Features.** A 2D Gaussian Process interpolates flux across time *and* filter, using a multivariate Gaussian kernel with a Wasserstein-1 term between filter throughputs (Eq. 1). This produces a flux + error estimate per filter at every time step, handling irregular sampling and missing bands.

**Model.** A Variational Recurrent Autoencoder (VRAENN): GRU encoder → bottleneck of size 1×10 (mean + diagonal covariance; the paper states this size was not optimized) → repeat layer → GRU decoder → dense output. Loss = log(weighted MSE) + KL divergence (Eq. 2). Trained with Adam (α=1e-4, β1=0.9, β2=0.999) in Keras/TensorFlow, on only 1% of the dataset (12,159 events) to simulate realistic early-LSST data volume. The resulting 1×10 encoded vectors are fed to a scikit-learn Isolation Forest (1000 estimators); the raw score is converted to a percentile.

**Uncertainty handling.** Four sources are identified — Poisson flux noise, GP flux uncertainty, photo-z error, and model uncertainty. The first three are propagated via 10-draw Monte Carlo; the model's own (network) uncertainty is explicitly *not* accounted for.

**Evaluation.** Events are ranked by anomaly score; a CDF of score is produced per class; percentile-plus-uncertainty cuts are applied (90th/95th/99th/99.9th percentile combined with σ_A/A thresholds); purity and "abundance" (anomalous-fraction ratio vs. expected input fraction) are the reported metrics.

**Results.** At the 95th percentile with σ_A/A < 0.01, SLSNe make up ~5% of the retained sample versus 0.03% of Ia/II in the original population — roughly a 4.5× over-representation — and the sample stays pure (≲10% contamination from majority classes). Removing catastrophic photo-z outliers (|z_phot−z_true|/z_true > 2) meaningfully improves purity at the strictest cuts, less so at 95%. About 65% of minority-class anomalies are flagged *before* peak brightness (useful for real-time follow-up); about 60% of majority-class false anomalies are flagged *after* peak. The method is biased toward brighter events, though not through a simple luminosity cut.

**Strengths.** No physical priors, so the method stays sensitive to genuinely unexpected phenomena; it works natively with irregular, aperiodic, multi-filter, real-time (partial) light curves — a contrast with prior work restricted to single-channel, well-sampled series.

**Limitations.** Untested on real data with an active follow-up campaign; strongly limited by photometric-redshift error, which is the dominant driver of false anomalies among majority-class supernovae; the bottleneck size (1×10) is untuned; the network's own model uncertainty is never accounted for.

**Reproduction note (what to build).** A simplified VRAE + Isolation Forest baseline: GRU encoder–decoder, small bottleneck, Isolation Forest scoring on the encoded vectors.

> **`Synthesis/Interpretation`** — TESS is single-passband, unlike PLAsTiCC's 6-filter *ugrizY*, so the GP's cross-filter Wasserstein term has no direct TESS equivalent. Reproducing this baseline faithfully therefore requires a single-band GP/interpolation step in place of Eq. 1 — an architectural adaptation the paper itself does not specify, since it never faced a single-band case. Per R8, this baseline must otherwise use the same split, preprocessing, and tuning budget as the proposed pipeline, so the *only* deliberate deviation from the paper should be this single-band substitution — everything else (bottleneck size, isolation-forest scoring, percentile evaluation) should be kept as close to the original as the TESS data allows.

**Role/Explainability.** Baseline 1, evaluated against Model C (VAE + CNN fingerprint) on Track A.

> **`Synthesis/Interpretation`** — This is not an XAI paper. Its only interpretability mechanism is the isolation-forest percentile score plus manual timing/class analysis — there is no per-feature or per-example explanation. Its main value to the project is as a **negative example**: a competent, well-validated anomaly ranker that offers *no* explanation layer at all. That gap is direct motivation for building the Contrastive Explanation Engine (Part III) — Villar et al. show that state-of-the-art detection performance and interpretability are currently solved separately in this literature, not jointly.

## 2. Webb et al. (2020) — Baseline 2 (Hand-Crafted Features + Clustering)

**Problem.** Manual evaluation cannot keep pace with wide-field survey data volume; supervised methods need labeled data and cannot discover unknown event types. The paper targets unsupervised discovery in fast (seconds-to-minutes cadence), aperiodic, non-folded light curves — i.e., data that cannot be phase-folded the way periodic variables usually are.

**Dataset.** The Deeper, Wider, Faster (DWF) program, DECam, continuous 20-second g-band exposures. Two fields: J04-55 (90 minutes, "stare" mode, 23,199 sources with ≥3 detections) and Antlia (80 minutes, stare + 5-point dithering, 62,354 sources with ≥3 detections). Cadence is ~60–68 seconds.

**Preprocessing.** NOAO High-Performance Pipeline; SExtractor source extraction; magnitude correction against SkyMapper DR2; a master catalogue built via 0.5″ cross-matching; non-detections replaced with the CCD's exposure detection upper limit.

**Features.** 25 features, mostly via the FATS package (some in-house), selected by PCA for large eigenvalues and drawn from prior literature (Richards 2011; Kim 2011/2014; Pichara 2012; full list in Appendix A1: amplitude, autocorrelation length, Beyond1Std, CAR mean/σ/τ, H1, Con, linear trend, MaxSlope, mean, mean variance, median absolute deviation, median buffer range %, pair slope trend, Q31, R21/R31, Rcs, skew, slotted ACF length, small kurtosis, standard deviation, Stetson KAC, variability index). Not restricted to folded/periodic features — this is what makes them usable on aperiodic data.

**Methodology.** A four-stage pipeline: (1) feature extraction; (2) HDBSCAN clustering (min cluster size = 5, Euclidean distance) separates "ordinary" clusters from candidate anomalies; (3) t-SNE for 2D visualization only, not cluster identification (its stochasticity makes it unsuitable for the latter); (4) the ASTRONOMALY package applies an sklearn Isolation Forest *independently within each HDBSCAN cluster* to rank light curves, with a GUI limited to the top 2000 ranked curves.

**Training/inference.** Not a trained model in the conventional sense — HDBSCAN and Isolation Forest are run per dataset, unsupervised, with no explicit train/test split. Isolation Forest hyperparameters beyond "sklearn implementation, Ting/Liu/Zhou 2008" are not stated.

**Evaluation.** Cross-matching against known catalogues (VSX, DES RR Lyrae, Catalina Surveys Southern Periodic Variable Star Catalogue); a completeness check; and the rank position of recovered anomalies within the top-N list.

**Results.** J04-55: 3 HDBSCAN clusters (98.7% "steady") plus 138 unclustered light curves → 6 variable sources found (5 catalogued, 1 newly discovered slow pulsating B star) plus 1 newly discovered flare on an RR Lyrae. Of 13 catalogued VSX variables in-field: 5 recovered, 3 fell below the detection threshold, 5 were correctly left in the "steady" cluster (their periods exceed the 90-minute observing window). Antlia: 37 HDBSCAN clusters (93.5% "steady," the remainder mostly dithering/CCD-edge/cosmic-ray artifacts) → the G2 cluster held 6 variables (3 new); 2,169 unclustered curves held 9 more (3 new, including an ultrafast ~5-minute flare, likely on an M-dwarf). All 9 unclustered variables were found within the top 280/2000 ranked anomalies; the ultrafast flare within the first 600/2000. Speed: feature extraction ~110 s per 1,000 curves (parallelized); HDBSCAN ~2 minutes; ASTRONOMALY <2 minutes; the full 70,000-curve pipeline is ready for review in ~20 minutes.

**Strengths.** Recovers known variables across multiple independent catalogues; genuinely discovers new variables and flares; fast enough for near-real-time use on tens of thousands of curves; dual verification (clustering + ranking) cross-validates completeness.

**Limitations.** Dithering massively increases cluster count (4 → 37) due to instrumental artifacts, diverting clustering "budget" away from astrophysical discovery; still requires manual/visual vetting via the GUI (human-in-the-loop, not fully automated); demonstrated on only two single-night fields (a small fraction of the full DWF dataset — 250+ hours across 17 fields is left as future work); completeness is inherently bounded by the observing-window-vs-source-period relationship.

**Reproduction note (what to build).** A hand-crafted-feature baseline (FATS- or tsfresh-derived) positioned against the project's own 13-dimensional fingerprint.

> **`Synthesis/Interpretation`** — Webb's pipeline is *cluster-first, then score*, which is architecturally distinct from a direct classifier or a single-pass anomaly ranker. The comparison against Model B may end up mattering more at the level of feature representation (hand-crafted 25-feature vector vs. the project's 13-dimensional morphological fingerprint) than at the level of requiring an identical HDBSCAN+Isolation-Forest architecture. Per R8, whichever architecture is chosen for this baseline must still use the same split, preprocessing, and tuning budget as the rest of the project.

**Role/Explainability.** Baseline 2, evaluated against Model B (VAE + hand-crafted fingerprint) on Track A.

> **`Synthesis/Interpretation`** — There is no formal explanation mechanism here either; "interpretability" is entirely human visual inspection via the GUI's t-SNE/anomaly-score views. This is relevant to the project as a **validation-pattern precedent** (visual sanity-checking of flagged candidates), which could usefully inform a qualitative error-analysis supplement — but it is not itself a substitute for the project's planned quantitative explanation protocol.

## 3. Dasgupta (2025) — CLARA — Baseline 3 (URF + Cosine Similarity to Reference Library)

**Problem.** Two questions are posed: (a) how does synthetic training-set design affect Unsupervised Random Forest (URF) performance and generalization across independent TESS sectors; (b) do URF anomaly scores correlate with genuine astrophysical phenomena, enabling identification/clustering of transit-like signals?

**Dataset.** TESS SPOC 2-minute cadence, Sectors 1–5 (87,858 light curves processed, per §3.4.1). TOI catalog via ExoFOP-TESS; Gaia DR3 for astrometric/stellar parameters; SIMBAD for object-type classification.

**Features.** Following Crake & Martínez-Galarza (2023): the first 3,000 flux points stacked with 1,000 Lomb-Scargle periodogram frequency points (via astropy.timeseries) → a 4,000-dimensional vector.

**Model.** An Unsupervised Random Forest (URF) — a RandomForestClassifier trained to distinguish real from synthetic light curves. Four synthetic-set design variants are tested: URF1 (uniform random sampling, baseline), URF2 (fixed MG23 hyperparameters), URF3 (real TOI vectors used as the "synthetic" class — later shown to overfit to its training sector, Appendix B.1), and URF4 (batman-generated transit models with varied duration/cadence/noise — the main variant used throughout). URF4 fixes the real set to 1,500 TESS SPOC Sector-2 curves against a synthetic set of 300 curves.

**Training.** RandomizedSearchCV over a hyperparameter space (Appendix B.2: n_estimators — 10 values in [50,200]; max_features — sqrt, log2; max_depth — [100–1000, None]; min_samples_split — 2/4/7/10; min_samples_leaf — 1/2; bootstrap — True/False; warm_start — True/False). The synthetic-parameter grid for URF4 spans n_curves [100,200,300] × duration_days [13.5,27.0] × cadence_min [2.0,10.0] × noise_ppm [50e-6,100e-6,200e-6] = 36 sub-variants.

**Anomaly scoring.** A terminal-node population heuristic (Baron & Poznanski 2017; Crake & Martínez-Galarza 2023): similarity score S = the average fraction of real points sharing a terminal node across trees; anomaly score = 1 − S. A combined score is built with a detection/interpretability trade-off parameter α: S_combined(α) = w_recall·R_norm + w⁻¹_anomaly·A_inv + w_δ·Δ_norm + w_importance·I_norm + w_range·P_inv (Eq. 4), with Detection-weight = α and Interpretability-weight = 1−α. Three α variants are reported (0.3, 0.5, 0.9); an ensemble fusion of the α=0.3 and α=0.9 variants is built via N-WRSS (weights 0.8/0.2, with a square-root transform to dampen single-model dominance).

**Key hyperparameters.** Real:synthetic ratio fixed at 1500:300 for URF4; α = 0.3/0.5/0.9 for the headline variants; N-WRSS weights 0.8/0.2; anomaly threshold N-WRSS ≥ 0.6 chosen as the "practical operating point" (vs. 0.35 as permissive and 0.9 as overly strict).

**Evaluation.** A six-metric framework (Table 1): TOI Recall AUC, TOI Importance AUC, Mean Importance (Top 20%), Binary TOI Recall, Anomaly Rate, and Percentile Range. TOI Importance = SNR × Depth(ppm) × Duration(days), normalized to [0,1].

**Results.** In a cross-sector test (5 sectors, 384,000 curves scored across α variants), α=0.9 gives the best Binary TOI Recall in all 5 sectors (100% consistency); α=0.5 gives the best TOI Importance Top-20% and the lowest Anomaly Rate in all 5 sectors; α=0.3 wins the Top-10% Importance Range in 3/5 sectors. A Monte Carlo injection-recovery test (80 runs, 20 injected + 1,980 real curves per run) at N-WRSS ≥ 0.6 gives mean precision 0.53 ± 0.18 (95% CI 0.49–0.57) and mean recall 0.74 ± 0.24 (95% CI 0.69–0.79). A false-positive analysis (Table 9, 187 non-injected curves) breaks down as: binaries (100/187, ~53%), generic stars (50), variables (20), planets/planet-like (8), multiples (6), unclassified (3) — i.e., the false positives are astrophysically interpretable, not noise-driven. A high-anomaly/low-similarity diagnostic (Fig. 12) yields **zero** candidates: no high-scoring anomaly in this dataset lacked morphological similarity to a known SIMBAD class.

**Strengths.** Fully open-source; runs entirely CPU-only on a personal desktop (Intel i3-8100, 32 GB RAM, no GPU) — 87,000+ curves processed without a GPU; documented hyperparameter search; controllable behavior via α; morphological/astrophysical grounding via SIMBAD + Gaia cross-matching; rigorous Monte Carlo validation with confidence intervals.

**Limitations (§4.3).** Results apply only to 2-minute SPOC targets (FFI data would need recalibrated thresholds); TOI-dependent validation risks bias (partly mitigated by SIMBAD checks and injection-recovery); simplified synthetic models and truncated curves may omit complex or long-duration anomalies.

**Reproduction note (what to build).** A simplified URF + cosine-similarity baseline: (1) flux + Lomb-Scargle stack; (2) URF trained on real-vs-synthetic data (the URF4 approach); (3) terminal-node-population scoring; (4) cosine-similarity classification against reference exemplars. Per R8, this needs the same split, preprocessing, and tuning budget as the rest of the project.

**Role/Explainability.** Baseline 3, evaluated against Model D (the proposed pipeline) on Track A, plus a descriptive reference-library similarity score that is *not* treated as formal Track B evidence.

> **`Synthesis/Interpretation`** — The only interpretability mechanism here is post-hoc: cosine similarity to a SIMBAD reference set plus Gaia correlations. It is descriptive, not per-decision, and the paper itself does not claim it as XAI. The single most important result for this project is the **zero high-anomaly/low-similarity finding**: in this dataset, every high-scoring anomaly turned out to resemble a known class. That is direct literature evidence that a reference-similarity-only approach may *not* reliably surface genuinely novel signals without a rigorous, non-circular specificity test — this is the concrete motivation for the project's R12 protocol (Track B) and reinforces why a contrastive explanation layer, rather than similarity-scoring alone, is needed to distinguish "rare-but-known" from "genuinely novel."

# PART II — Closest Domain Precedent

## 4. Crake & Martínez-Galarza (2023) — "Linking Anomalous Behaviour with Stellar Properties" (MNRAS)

**Contribution.** Applies Unsupervised Random Forest (URF, from Martínez-Galarza et al. 2020 / "MG21" on *Kepler*) to two years of SPOC-reduced TESS light curves (Sectors 1–24, >400,000 curves, >200,000 unique targets). Produces a public catalogue of anomalous objects, a morphology-based classification scheme, and a comparison of anomalousness against stellar evolutionary stage (via Gaia CMD) and against the earlier *Kepler* results.

**Methodology.** Feature vector = 3,000 uniformly resampled/normalized flux points + 1,000 Lomb-Scargle power values (log-spaced periods, 4h–27d) → a 4,000-dimensional vector — this is exactly the representation Dasgupta's CLARA (Baseline 3) adopts. URF procedure: (1) train a Random Forest to distinguish real data from synthetic data built by independently sampling each feature's marginal distribution (which destroys real feature correlations); (2) similarity score per object = the average fraction of the population sharing its terminal node across trees; anomaly score = 1 − similarity. Hyperparameters are tuned via 3-fold random-search CV; the score is averaged over 10 independent RF realizations. Anomalies are classified purely by visual/morphological inspection — sinusoidal, modulated, peaked, dips, irregular, multi-body/transit, long-period-variable, artefact, no-label (Table 2) — deliberately *not* by astrophysical class. Known-class anomalies (white dwarfs, eclipsing binaries, pulsators, YSOs, giants) are cross-matched against SIMBAD and external catalogues.

**Key findings.** A bimodal anomaly-score distribution: ~82% "bulk" (score < 0.6), ~11% anomalous (>0.9), consistent across all 24 sectors (std 0.02 sector-to-sector). Anomaly score is stable across repeated observations for most objects (95% have σ < 0.1); the high-variance minority are candidate non-persistent (transient) anomalies. Dominant anomaly-driving classes: white dwarfs, instability-strip pulsators (RR Lyrae, δ-Scuti, Cepheids), YSOs with irregular obscuration variability (the closest analogues in this catalogue to Boyajian's Star), and eclipsing/multi-body systems with unusually deep or long transits. Crucially, **anomaly is population-relative, not absolute**: the same method applied to *Kepler* versus TESS recovers *different* anomalous classes (e.g., red giants score high in *Kepler* but low in TESS) because of different stellar populations in the two surveys — the authors treat this as a central methodological finding, not an artifact. A cross-check against 9 published "bona fide" anomalous objects (Table 3) found 8/9 scored highly; the one miss had a pulsation period below the method's frequency-resolution floor. A case study: the method detected anomalous Betelgeuse variability ~10 months before its well-known 2019 dimming event.

**Relevance.** This is the closest domain baseline in the entire corpus (same instrument, same general task). URF is a natural classical baseline against VAE-based novelty scoring; the flux+Lomb-Scargle concatenation is a validated hybrid representation (and the direct ancestor of Baseline 3's feature vector); Table 2's taxonomy is a ready-made, human-interpretable vocabulary for morphology classes; the population-relativity finding directly supports moving toward real (not purely synthetic) reference curves; the multi-sector variance check is a precedent for uncertainty quantification; and the Table 3/Betelgeuse protocol is a reusable template for validating a candidate anomaly such as the project's worked example S8.

**Limitations.** Explainability is limited to global feature importance (Fig. 3) plus labour-intensive manual visual inspection — no automated, per-object, contrastive, or structured explanation exists here. The method cannot separate instrumental artefacts from real anomalies on its own; Sectors 22–23 were excluded due to artefact contamination, and triage remained manual throughout. It misses most known transiting exoplanets (only 6.3% of TOIs flagged) since it does not use folded/stacked curves — a known blind spot. It is purely classical ML (feature engineering + Random Forest), not directly comparable in representational capacity to a VAE. Short-period pulsators below ~4 hours are undetectable by construction (the periodogram's frequency floor).

> **`Synthesis/Interpretation`** — Because this paper is not one of the three formally reproduced baselines but is nonetheless the closest same-instrument precedent, its main implementation value is as a **source of reusable protocol**, not as competing architecture: (1) the Table 3/Betelgeuse-style external validation is a strong template for validating S8 or any other flagged candidate against independent literature; (2) the population-relativity finding is a caution that must inform how "novelty" is defined and reported in this project — an object flagged as anomalous relative to the project's reference population is not automatically astrophysically anomalous in an absolute sense, and the write-up should be explicit about this; (3) its own admission that explainability here is "manual visual inspection only" is further, independent evidence (alongside Baseline 3's zero high-anomaly/low-similarity result) that the domain currently lacks a structured, per-object explanation method — reinforcing the research gap this project addresses.

# PART III — XAI Foundations for the Contrastive Explanation Engine

The project's own strategic analysis identified the Contrastive Explanation Engine as its most novel component. These six papers are the literature basis for that engine's design, ordered from general background to the most directly transferable mechanisms.

## 5. Lieu (2025) — "A Comprehensive Guide to Interpretable AI-Powered Discoveries in Astronomy" (*Universe*, review)

**Core idea.** Predictive accuracy alone is scientifically insufficient — trust, physics validation, reproducibility, and bias detection all require understanding *why* a model reached a conclusion. The paper formally separates three concepts: transparency (is the internal machinery accessible), interpretability (can a human understand the input–output relationship/decision logic), and explainability/XAI (post-hoc, human-understandable explanations for black-box models — e.g., SHAP, LIME, saliency, attention). Its central claim: no single interpretability technique gives a complete or fully faithful picture, so multiple methods should be combined and checked for agreement, and explanations should be *actively tested* (e.g., perturbing or removing a flagged feature and observing whether the prediction changes) rather than just visualized and trusted.

**Catalogued techniques (a survey, not an empirical study).**
- *Feature importance*: Gini (tree-based; can overweight high-cardinality/correlated features) vs. permutation importance (model-agnostic, held-out data, more reliable but costlier) — these can disagree substantially on the same features.
- *Saliency for deep nets* (also applicable to time series, per the paper's Table 1): vanilla gradient (noisy, can saturate); guided backprop/SmoothGrad (cleaner, but can suppress negative evidence); Integrated Gradients (axiomatically grounded, but baseline-sensitive); Grad-CAM (coarse, layer-dependent, CNN-specific).
- *Model-agnostic*: SHAP (Shapley-based, theoretically principled via efficiency/symmetry/dummy/additivity axioms, but expensive — needs TreeSHAP-style approximation); LIME (cheaper local surrogate, sensitive to sampling/kernel choice, less stable).
- *Interpretable-by-design*: rule-based/decision trees (transparent, lower accuracy ceiling); attention (explicit weights, useful for visualization, but flagged as not guaranteed causal — citing the "attention is/is not explanation" debate); symbolic regression (closed-form equations, most interpretable/"white-box," but expensive and noise-sensitive); interpretable latent representations (β-VAE disentanglement, latent traversals, conditional generation, post-hoc PCA/clustering on the latent space); physics-informed neural networks; and prototype/exemplar-based explanation — "this input is class Y because it resembles known examples of Y" — which the paper explicitly names as the natural approach for **unsupervised settings with no ground truth**.
- A lookup table (Table 1) matches data type (image/tabular/time-series) and interpretability goal to recommended techniques.

**Findings/positions.** The paper documents concrete cases where interpretability methods enabled new discoveries: saliency-map analysis found a new pulsar in archival data; Grad-CAM on a cluster-mass CNN showed the network used X-ray outskirts rather than bright cores, matching independent physical understanding; combining saliency with symbolic regression produced a new interpretable model of galaxy assembly bias. It recommends combining model-specific (efficient, architecture-aware) with model-agnostic (broadly applicable, slower/less faithful) methods, and flags documented sanity-check *failures* of gradient/saliency methods (visually similar maps even after randomizing model weights) — these should not be trusted uncritically. It also notes there is currently **no standardized astronomy-specific benchmark** for evaluating explanation quality.

**Limitations.** A review, not a new method or dataset — needs primary-literature follow-up before implementation (which is exactly what Papers 6–10 below provide). It is not specific to time-domain light curves; most worked examples are imaging or tabular/spectral, and light-curve-specific examples are thin (mainly the pulsar-saliency case). It stresses that no method is fully faithful, which sets a realistic ceiling on what any explainability claim in this project can assert. There is no agreed XAI evaluation metric for astronomy, so evaluation criteria must be defined independently by the project itself.

**Relevance.** This paper supplies the correct taxonomic vocabulary for the whole engine: a contrastive explanation engine is a form of prototype/exemplar-based explanation — the paper's own recommended approach for unsupervised, no-ground-truth settings; the morphological fingerprint is a structured, interpretable representation analogous to hand-crafted features, to which feature-importance tools (permutation importance, SHAP) can be applied; a novelty/anomaly score benefits from the paper's "test the explanation" discipline (perturb-and-check).

> **`Synthesis/Interpretation`** — Concrete next steps this paper motivates: apply permutation importance or SHAP to the fingerprint vector as a sanity check; if a CNN fingerprint extractor is used (Model C), pair it with Grad-CAM/Integrated Gradients plus a randomized-weight sanity check (this paper explicitly warns that gradient-based saliency can look plausible even on a randomized network); use latent traversals or β-VAE disentanglement diagnostics on the VAE latent space as a secondary interpretability check. The paper's "combine multiple methods" recommendation is consistent with — and a partial justification for — the project's multi-component design (fingerprint + contrastive comparison + novelty score) rather than relying on any single explanation mechanism. Given its faithfulness caveat, the contrastive explanation engine should be described in the eventual paper as an interpretability *aid*, not a definitive causal account of why the model flagged a star.

## 6. Dhurandhar et al. (2018) — Contrastive Explanations Method (CEM)

**Core idea.** A complete explanation should state not only what is minimally *present* (a **pertinent positive**, PP) but also what is minimally and critically *absent* (a **pertinent negative**, PN): "*x* is classified as *y* because features f₁,…,fₖ are present and features fₘ,…,fₚ are absent." A PN is conceptually distinct from a "negatively relevant feature" as produced by LRP or LIME: a PN's absence is *necessary* for the class to hold (it supports the classification), whereas a negatively relevant feature *devalues* the hypothesis — these are different kinds of evidence, not the same idea under different names.

**Methodology.** For an example x₀ with predicted class t₀, CEM solves two optimization problems over a perturbation δ via projected FISTA:
- **PN** — the smallest δ added to the "missing"/background space of x₀ that flips the top-1 prediction, with elastic-net (L1+L2) regularization for sparsity and an optional autoencoder-reconstruction penalty keeping δ near the data manifold.
- **PP** — the smallest δ drawn from x₀'s *existing* content that, alone, is sufficient to keep the same top-1 prediction, using the same elastic-net plus optional autoencoder terms.

The autoencoder term is optional; it was dropped for two of the three validation datasets (procurement fraud, fMRI) because it was judged data-insufficient/unsuited for a learned manifold model there.

**Results.** Validated on MNIST, a procurement-fraud invoice dataset, and ABIDE I autism fMRI data. Domain experts rated CEM's PPs as matching their own judgment 90.3% of the time, versus 88.2% for LRP and 86.6% for LIME (used as a proxy since neither method natively produces PPs); PNs matched expert judgment 94.7% of the time (no fair proxy existed for the other methods on PNs). A separate check found CEM's PPs and PNs were 100% effective at maintaining or flipping the class label when fed back into the classifier, across all three datasets.

**Limitations.** The authors acknowledge some information loss in this explanation format. The autoencoder-manifold term needs a well-trained autoencoder, which is not always obtainable (and was not used for the fraud/fMRI datasets). PNs are most useful when classes are "close" (e.g., flu vs. pneumonia); when classes are very different, many PNs may exist and risk "overwhelming the user" — PN utility is domain- and class-geometry-dependent. The method is post-hoc and optimization-based (iterative FISTA per example) — it explains one input at a time, not the model globally.

**Relevance.** This is the single most directly transferable paper in the corpus. The (present, absent) format maps naturally onto explaining a flagged star: "S8 is anomalous because dimensions [x, y, z] are present, and [expected feature] is absent." Concrete transfers: (a) apply the PP/PN objective to the 13-dimensional fingerprint vector rather than to pixels — a much lower-dimensional, more tractable search space; (b) use the elastic-net sparsity term to return a *minimal* fingerprint subset rather than reporting all 13 dimensions at once; (c) the project's existing VAE reconstruction term is a natural drop-in replacement for CEM's optional autoencoder-closeness penalty, since the project already has a trained VAE for exactly this purpose.

> **`Synthesis/Interpretation`** — This paper should be treated as the primary algorithmic backbone of the Contrastive Explanation Engine, with the other five XAI papers contributing framing (Miller), a manifold-plausibility safeguard and distance-metric choice (Wachter), a structural precedent for the reference library the PP/PN search draws on (ProtoPNet), and a narrative-delivery layer (van der Waa). Its validated 90–95% expert-agreement rates are also a useful benchmark to cite when designing this project's own domain-expert evaluation of explanation quality, if one is planned.

## 7. Chen et al. (2019) — ProtoPNet

**Core idea.** "This looks like that" — interpretability via having the network compare parts of a new input against learned prototypical parts, then base its prediction on a weighted combination of similarity scores. This is a built-in reasoning process: the same comparisons used to explain a decision are the ones used to make it, rather than being fitted after the fact.

**Methodology.** A CNN backbone *f* produces a convolutional feature map; a prototype layer computes squared L² distance (not inner product) between learned prototype vectors and all same-shaped feature-map patches, converts these to similarity scores, and max-pools per prototype; a final bias-free fully-connected layer turns similarity scores into class logits. There is a fixed number of prototypes per class. Training proceeds in three stages, cycled as needed: (1) SGD on the conv layers and prototypes jointly, using cross-entropy plus a cluster cost (pulling each image's patches toward a same-class prototype) plus a separation cost (pushing patches away from other-class prototypes); (2) prototype projection — each prototype is snapped to its nearest real training-image patch, so it becomes visualizable as an actual image crop, with no decoder needed; (3) convex optimization of the last layer to sparsify prototype-to-non-matching-class connections.

**Results.** Comparable accuracy to the same non-interpretable backbone (at most 3.5% lower) on CUB-200-2011 birds and Stanford Cars; combining several ProtoPNets approaches state-of-the-art attention-based accuracy while retaining full interpretability, which the authors state existing attention-based interpretable models cannot achieve. A theorem (2.1) gives the conditions under which prototype projection preserves the prediction.

**Limitations.** The number of prototypes per class is a fixed hyperparameter (10/class in the paper's experiments), not learned. Prototypes are fixed small spatial patches (H₁=W₁=1 in the experiments), which assumes spatially localizable, patch-like discriminative structure — an assumption that may not transfer cleanly to 1D time-series morphology. There is a real, if modest, accuracy cost versus a non-interpretable baseline. Theorem 2.1's guarantee relies on explicit assumptions (A1–A4), so it is conditional, not universal. Prototypes whose nearest training patches span multiple classes generally correspond to non-discriminative background and are pruned.

**Relevance.** A natural precedent for the project's morphological-fingerprint and novelty-scoring components, which already resemble a prototype/nearest-reference architecture. Transfers: (a) the projection-onto-real-training-patch design supports the project's planned move from synthetic to real reference light curves; (b) the pruning criterion (a prototype whose nearest neighbors span multiple classes is non-discriminative) gives a concrete, reusable criterion for curating the reference-star library rather than including every candidate reference star by default.

> **`Synthesis/Interpretation`** — This paper is a structural, not a plug-and-play, precedent: the project is working with 1D light-curve morphology rather than 2D image patches, so the spatial-patch machinery (feature-map patches, H₁=W₁=1) does not transfer directly. What transfers is the *design principle* — snap abstract references to real, verifiable examples, and prune references that don't discriminate cleanly between classes — which applies just as well to curating a library of real reference light curves for the contrastive engine's PP/PN search (Dhurandhar) as it does to image patches.

## 8. van der Waa et al. (2018) — Contrastive Explanations for Reinforcement Learning

**Core idea.** Explanations should answer contrastive "why this and not that" questions in terms of a **fact policy** (what the agent actually does) versus a **foil policy** (a user-specified alternative), described via expected *consequences* rather than raw state features or numeric rewards — the authors argue the latter are not inherently meaningful to non-expert users.

**Methodology.** The MDP ⟨S,A,R,T,λ⟩ is extended with translation functions k: S→C (states → a small set of human-interpretable Boolean concepts, e.g., "next to a wall") and t: C×A→Pr(O) (state-action pairs → probabilistic, human-labeled outcomes, flagged positive/negative). Given a user's foil description, a preference value function Q_I is built via simulation (weighted by distance from the current state using a Gaussian/RBF kernel, discounted by λ_f) and combined with the agent's learned Q_t (Q_f = Q_t + Q_I) to derive a foil policy π_f. Both the fact policy π_t and the foil policy π_f are rolled out through a transition model T into trajectories, mapped through k and t into concept/outcome sequences, and inserted into narrative templates. The final contrastive explanation is built from the relative complement/symmetric difference between the fact and foil paths.

**Results.** A worked method plus a pilot survey (82 participants) on a grid-world navigation task, comparing exemplar explanations that varied in length, information density, action-vs-policy framing, and short-term-vs-distant consequences. Participants preferred explanations addressing strategy/policy over single actions, and preferred more information over less.

**Limitations.** Explicitly a "pilot"/"small user study" on a simple grid-world; the authors caution that participants may have rated single-action explanations as trivial simply because the optimal action was already obvious in that toy case. The concept-translation functions (k, t) must be designed and trained (e.g., via binary classifiers) — the vocabulary of concepts is not automatic. The computational cost of simulating multiple policies' consequences in large state spaces is flagged as a future scalability concern. The whole approach assumes a simulatable transition model T — it targets sequential decision problems, not static classification or anomaly detection.

**Relevance.** This paper is **not architecturally transferable** — there is no MDP or policy to simulate in a static anomaly-detection setting — but it is the clearest available template for a *narrative layer* sitting on top of CEM/ProtoPNet-style outputs. What transfers: (a) frame the final explanation as an explicit fact-vs-foil contrast, e.g., "S8 is flagged because [present features], unlike [nearest known class], which would show [contrasting features]"; (b) the empirical finding that users preferred higher-level, information-rich, policy/summary-style explanations over single-feature ones supports generating a synthesized narrative per flagged star, rather than a raw list of fingerprint deltas.

> **`Synthesis/Interpretation`** — Given as much, this paper earns the lightest coverage of the six XAI sources: its architecture is not reusable, and its empirical result (a small pilot survey on a toy grid-world) should not be over-cited as strong evidence — it is suggestive, not conclusive, about explanation-format preferences in this project's very different domain. Its main contribution here is vocabulary and structure (fact/foil framing, narrative templates), not a transferable algorithm.

## 9. Wachter, Mittelstadt & Russell (2017) — Counterfactual Explanations Without Opening the Black Box (GDPR)

**Core idea.** A decision can be explained without exposing internal model logic, by stating the smallest input change that would produce a different, specified output: "Score p was returned because variables V had values (v1,v2,…). If V instead had (v1′,v2′,…), score p′ would have been returned." This sidesteps having to convey millions of interdependent weights or disclose proprietary internals.

**Methodology.** Formalized as an optimization problem: hold the trained weights fixed, and search for the closest point x′ to input x such that the output changes to a target y′ (Eq. 1–2). This is solved by minimizing a weighted combination of prediction-target loss and a distance term, iteratively increasing the loss weight (λ) until convergence, using Adam with multiple random initializations (which counters local minima and yields diverse counterfactuals). The **distance function** matters a great deal empirically: unweighted squared Euclidean distance produces artefacts — e.g., a discrete race variable taking fractional or negative values on the LSAT dataset, or GPA being over-weighted relative to LSAT purely due to scale differences. The recommended default is L1 (Manhattan) distance weighted by the inverse median absolute deviation (MAD) — sparsity-inducing and outlier-robust. Discrete/categorical variables are handled by clamping across separate optimization runs and keeping the closest solution. Demonstrated on a neural net predicting first-year law-school grade from race/GPA/LSAT, and a neural net predicting diabetes risk from 8 clinical variables (Pima Diabetes). The second half of the paper is a legal argument mapping counterfactuals onto three purposes of explanation (understand, contest, alter future decisions) against specific GDPR provisions (Recital 71, Articles 12–15, 22).

**Limitations.** No causal model is used — variables are treated as independent (§III.C), a deliberate simplification; the authors flag that unanticipated dependencies between changed attributes and others "may undermine the utility of counterfactuals as guides for future behaviour." A single counterfactual is not evidence of irrelevance for unchanged variables (§II.D). There is an off-manifold/adversarial risk: nothing guarantees the synthetic counterfactual is realistic, especially in high-dimensional structured spaces. There is no consensus distance metric — the question is explicitly deferred to future work. Counterfactuals alone do not provide statistical evidence for fairness/bias auditing (large-scale statistical analysis is preferred for that). The method is demonstrated only on small, fully-connected nets on tabular data — not validated on unsupervised, latent-variable, or time-series settings.

**Relevance.** Equations 1–2 are a direct template for a latent-space or feature-space counterfactual search in a VAE: given an anomalous point, find the nearest point (in latent or morphological-feature space) the model would score as "normal," holding weights fixed. The L1/MAD-weighted distance is directly transferable to feature scaling across morphological descriptors, since period, depth, and duration span very different numeric ranges and would otherwise produce the same scale artefacts the paper documents on GPA vs. LSAT. The paper's independence-assumption warning is directly relevant here: light-curve features are not independent (e.g., transit depth and duration are physically coupled), so perturbing one feature at a time risks generating physically implausible/off-manifold synthetic curves. This argues both for a validity/plausibility check on any generated counterfactual and for running two independent validation tracks (Track A/Track B) rather than trusting a single pass. The paper's own caveat — "a single counterfactual is not proof of irrelevance" — should directly shape how claims are phrased in the project's write-up: a counterfactual supports a contrastive *narrative*, not a causal-importance *ranking*, unless corroborated by other evidence. The GDPR/legal sections (§V) are not relevant to this project.

> **`Synthesis/Interpretation`** — Alongside Dhurandhar (2018), this is one of the two core algorithmic sources for the Contrastive Explanation Engine. In practice the two combine naturally: CEM's PP/PN search finds *which* fingerprint dimensions matter, while Wachter's L1/MAD-weighted counterfactual search (in the same fingerprint or latent space) finds *how far* those dimensions would need to move to look "normal" — giving both a categorical and a quantitative half of the same explanation. The independence-assumption warning here is arguably the single most important limitation to carry into implementation, since it directly justifies not treating any one counterfactual as a definitive causal claim about a flagged star, and it independently supports keeping a separate, non-circular specificity check (R12/Track B) rather than relying on the counterfactual search alone to certify novelty.

## 10. Miller (2019) — Explanation in Artificial Intelligence: Insights from the Social Sciences

**Core idea.** Most XAI work designs explanations from researcher intuition rather than the existing philosophy/cognitive/social-psychology literature on how humans actually generate, select, and evaluate explanations. Four findings should shape XAI design: (1) explanations are **contrastive** — people ask "why P rather than Q?" (a fact vs. a foil), even when Q is only implicit; (2) explanations are **selected, not exhaustive** — people pick one or two causes out of a larger causal chain, using biases such as abnormality, recency, controllability, intentionality, necessity/sufficiency, simplicity, generality, and coherence with prior belief; (3) **probabilities alone are not persuasive** — statistical/likelihood information is unsatisfying without an underlying causal story; (4) explanations are **social** — delivered as part of an interaction, governed by conversational norms (Grice's maxims: quality, quantity, relation, manner), and tailored to what the explainee is believed to already know.

**Methodology.** A structured survey (over 250 papers screened) covering: philosophical foundations of causality and explanation-as-answer-to-why; social attribution (Heider; Malle's model distinguishing reason, causal-history-of-reason (CHR), and enabling-factor explanations for intentional vs. unintentional behaviour); cognitive processes (abductive reasoning plus counterfactual simulation, explanation selection, explanation evaluation); and social/conversational explanation (Hilton's model, Grice's maxims, dialogue systems). The paper explicitly distinguishes **causal attribution** (identifying/extracting a causal chain) from **causal explanation** (the small, selected, audience-relevant subset actually communicated) — attribution is necessary but not sufficient for explanation. No new algorithm or empirical system is proposed; the contribution is a conceptual toolkit plus concrete design suggestions tied to each finding.

**Contribution.** A citable, structured mapping from human-subjects research onto XAI design guidance — chiefly the formal argument that contrastive (fact-vs-foil) explanation is the psychologically *correct default*, not merely a stylistic choice. It also supplies a widely-used vocabulary (fact/foil, causal attribution vs. explanation, abnormality/necessity/sufficiency/robustness as selection criteria, the "dilution effect" of irrelevant information) and names concrete failure modes in typical XAI practice: presenting full "attribution dumps" instead of selected, contrastive explanations, and leaning on probability/confidence scores as if they were self-sufficient explanations.

**Limitations.** No algorithm, benchmark, or empirical validation of its own — this is a synthesis, not new evidence. It explicitly scopes out a dedicated causality-theory survey and a survey of existing XAI methods except where directly relevant. It acknowledges that translating the surveyed psychological models into computational systems "is not a straightforward step," requiring interdisciplinary work. It is focused on "everyday" (local, single-decision) explanation rather than general/scientific explanation, by the author's own scoping choice. Some cited dialogue systems (e.g., EDGE) are noted by Miller himself as only anecdotally evaluated.

**Relevance.** This paper directly justifies the *structure* of a "Contrastive Explanation Engine": explanations should be phrased as "why anomalous rather than [a specific named foil]" — e.g., the nearest known variable-star class, or the population centroid in latent space — so every explanation should carry an explicit, named foil, not an implicit one. The causal-attribution vs. causal-explanation distinction is a direct critique of relying on raw reconstruction error or per-feature attribution *as if* that were itself an explanation — a genuine explanation requires a subsequent selection step, which is exactly what CEM's sparsity term and Wachter's distance-weighting provide algorithmically. The selection criteria (abnormality, necessity/sufficiency, robustness, simplicity/generality, coherence with prior domain knowledge) give a principled basis for ranking or filtering candidate explanatory features rather than reporting all of them. "Probabilities probably don't matter" is a direct caution against presenting the VAE's anomaly score or reconstruction error alone as "the explanation" — it should always be paired with a feature-level narrative. The dilution effect independently reinforces Wachter's L1-sparsity rationale: keep the reported explanatory features sparse. The social/conversational sections are lower priority for a static journal pipeline, but still useful for keeping written explanations relevant, proportionate, and non-redundant with what an astronomer reader already knows.

> **`Synthesis/Interpretation`** — Miller's paper functions as the theoretical umbrella over Papers 6–9: it is the reason the engine is being built as *contrastive* in the first place, rather than, say, a pure feature-importance dump. Its selection criteria (abnormality, necessity/sufficiency, simplicity, coherence with domain knowledge) are a natural rubric for the *final* narrative-generation step, after CEM/Wachter have produced candidate PP/PN features and counterfactual deltas — i.e., Miller's framework governs which of those candidate outputs actually get surfaced to the reader, and in what order.

# PART V — The Research Gap

Synthesizing across all 10 papers, three distinct gaps motivate this project, each supported by a specific, literature-stated finding rather than by assumption:

1. **No baseline in the direct anomaly-detection literature pairs strong detection performance with a structured, per-object explanation.** Baseline 1 (Villar) offers only a percentile score; Baseline 2 (Webb) offers only visual GUI inspection; Baseline 3 (Dasgupta) and its parent method (Crake & Martínez-Galarza) offer only global feature importance or descriptive post-hoc similarity. All three explicitly acknowledge this as a limitation in their own text — this is not an inference, it is stated by each paper.

2. **Reference-similarity scoring alone is not proven to catch genuinely novel signals.** Dasgupta's own high-anomaly/low-similarity diagnostic found zero cases where a high-scoring anomaly lacked resemblance to a known SIMBAD class, in that dataset. Combined with Crake & Martínez-Galarza's population-relativity finding (anomaly scores are relative to the reference population, not absolute), this is direct literature evidence that a similarity-only pipeline risks either (a) never certifying anything as truly novel, or (b) mistaking population-relative rarity for genuine novelty — motivating a dedicated, non-circular specificity protocol (R12/Track B) rather than treating detection alone as sufficient.

3. **The XAI-for-astronomy literature itself identifies the gap this project targets.** Lieu (2025) — the most astronomy-specific of the six XAI papers — states there is no standardized astronomy-specific evaluation benchmark for explanation quality, and that light-curve-specific worked examples of contrastive/exemplar-based explanation are essentially absent from the current literature it surveys. The five method-level XAI papers (6–10) that could fill this gap were developed entirely outside astronomy (tabular data, images, RL, fMRI, grid-worlds) and require deliberate architectural adaptation — none of them offer a light-curve-specific, validated instantiation.

> **`Synthesis`** — The gap, stated most precisely: **no existing method combines (a) an unsupervised, population-relative anomaly score for TESS light curves, (b) a non-circular test of whether a flagged object is genuinely novel rather than merely rare-but-known, and (c) a structured, contrastive, per-object explanation of *why* it was flagged, expressed in terms an astronomer can act on.** Each of the three elements exists somewhere in the reviewed literature; none of the ten papers combines all three, and several explicitly flag the absence of the third element as an open problem in their own limitations sections.

# PART VI — Literature Synthesis and Implications for the Proposed Methodology

> **`Synthesis`** — The remainder of this note is this project's own synthesis, built from the preceding sections; it should be read as an interpretation to be tested during implementation, not as a claim any of the 10 papers makes.

**On the detection side (Track A).** The three baselines span the plausible design space fairly well: a learned representation with no physical priors (Villar), a hand-crafted feature set with clustering (Webb), and a hybrid flux/periodogram representation with an unsupervised classifier (Dasgupta, building on Crake & Martínez-Galarza). Reproducing all three under the shared R8 protocol (identical split, preprocessing, tuning budget) is well-justified precisely because the papers differ enough in representation and model family that a fair, apples-to-apples comparison would otherwise be impossible — this is a genuine methodological requirement the literature itself creates, not an arbitrary constraint. Villar's single deliberate deviation (a single-band GP substitution for the multi-filter Wasserstein term) is the only place a baseline needs architectural adaptation to be usable on TESS at all; Webb's and Dasgupta's baselines translate to TESS with fewer structural changes.

**On the specificity side (Track B/R12).** Two independent findings — Dasgupta's zero high-anomaly/low-similarity result and Crake & Martínez-Galarza's population-relativity finding — converge on the same conclusion: detection/ranking performance and genuine novelty are not the same thing, and a project claiming to find *novel* anomalies needs a validation step beyond the detection score itself. This is the clearest, most literature-grounded justification available for keeping Track B/R12 as a separate, non-circular protocol rather than folding specificity into Track A's metrics.

**On the Contrastive Explanation Engine.** The six XAI papers divide cleanly into three roles: Miller (2019) supplies the theoretical justification and selection rubric (why contrastive, and which candidate features/deltas should be surfaced); Dhurandhar (2018) and Wachter (2017) supply the two core algorithmic mechanisms (categorical PP/PN search and quantitative counterfactual search, both directly applicable to the 13-dimensional fingerprint or the VAE latent space, both benefiting from L1/MAD-style sparsity to avoid Miller's "dilution effect"); Chen (2019) and van der Waa (2018) supply design principles rather than transferable code — a reference-library curation criterion and a fact-vs-foil narrative template, respectively — while Lieu (2025) supplies vocabulary, a "combine and cross-check methods" discipline, and an explicit warning that no single technique here should be treated as fully faithful.

**Practical implementation order suggested by the literature itself** (this ordering reflects dependency, not the papers' publication order):
1. Build the fingerprint/latent representation (informed by Baselines 1–3 and Crake & Martínez-Galarza's validated flux+Lomb-Scargle representation).
2. Run Track A detection and Track B/R12 specificity checks before investing in explanation, since Dasgupta's own experience shows a detection pipeline can look successful while still failing a specificity check.
3. Implement the PP/PN search (Dhurandhar) and the feature-space counterfactual search (Wachter) against the fingerprint, using L1/MAD-weighted distance.
4. Apply Miller's selection criteria to filter/rank the candidate PP/PN features and counterfactual deltas down to a sparse, non-diluted set.
5. Wrap the result in a fact-vs-foil narrative (van der Waa's template), naming an explicit foil (nearest known class or population centroid) per Miller's contrastive-explanation requirement.
6. Cross-check with at least one independent, model-agnostic method (permutation importance/SHAP, per Lieu) before trusting any single explanation, and consider a Table-3/Betelgeuse-style external validation (Crake & Martínez-Galarza) for any headline flagged candidate such as S8.
